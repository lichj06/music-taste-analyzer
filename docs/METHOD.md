# 方法学

本文说明 `music-taste-analyzer` 每一项数字是怎么算出来的、以及它**在什么情况下不可信**。

> 原则：**能本地算的绝不经模型，模型只负责它擅长的语义描述。**

---

## 一、为什么是"两路证据"

一个纯粹的声学管线能告诉你"频谱质心 3521 Hz"，但说不出"这是 J-Pop 还是 Trance"。
一个纯模型管线能写出漂亮的风格分析，但你**无法验证它有没有在编**。

所以本项目把两者放进同一份报告：

| 路 | 来源 | 性质 | 可信度判断 |
|---|---|---|---|
| A | 本地 `numpy` 信号处理 | 可复现、可验证 | 你自己就能重算 |
| B | 多模态模型听完后描述 | 语义丰富 | 拿 A 的数字去交叉检查 |

举个实际例子：模型说某首歌"动态被压得很死"，你去报告里看**波峰因数**那一行 —— 如果真是 8 dB 以下，说明它听对了；如果写着 15 dB，那它在编。

**这就是这套设计的全部意义：让两路互相证伪。**

## 二、预处理

```python
ffmpeg -v error -t 90 -i <path> -ac 1 -ar 22050 -f s16le -acodec pcm_s16le -
```

- **单声道 / 22050 Hz / s16le** —— 统计特征不需要立体声和高采样率，减半算力
- **只取前 90 秒** —— 对分布统计足够，且长曲不会拖垮批处理
- 采样点归一化到 `[-1, 1]` 的 `float32`

**分帧**：`NFFT = 2048`，`HOP = 512`，Hann 窗。22050 Hz 下每帧约 93 ms，重叠 75%。

## 三、调性判定（`key_of`）

用的是 **Krumhansl-Kessler 调性轮廓**（1990），业界经典方法，不是深度学习。

```
色度向量 chroma[12]
  ↓ 取 65–2000 Hz 频段（聚焦和声区间，滤掉贝斯基频和镲片噪声）
  ↓ 按音高类累计能量，归一化到和为 1
  ↓ 对 12 个主音 × 2 个调式 = 24 个候选，逐个做旋转后与模板求 Pearson 相关
  ↓ 取相关最高者为主调
```

```python
PROFILE_MAJOR = [6.35, 2.23, 3.48, 2.33, 4.38, 4.09,
                 2.52, 5.19, 2.39, 3.66, 2.29, 2.88]
PROFILE_MINOR = [6.33, 2.68, 3.52, 5.38, 2.60, 3.53,
                 2.54, 4.75, 3.98, 2.69, 3.34, 3.17]
```

**报告里的两个数**：

| 字段 | 含义 |
|---|---|
| `key_corr` | 最佳相关的绝对强度。**越接近 1 越确信** |
| `key_margin` | 与**关系调**（大调下方小三度 / 小调上方小三度）的相关差值 |

**`key_margin` 是关键**。关系大小调共享全部音级，光看相关值很容易在两者间摇摆；差值大才说明判定稳。

**不可信的情况**：
- 无调性 / 半音阶密集的作品 → `key_corr` 会整体偏低
- 频繁转调 → 单一调性描述本身就失效
- 强烈失真的吉他墙 → 色度被噪声抹平

**看到 `key_corr < 0.6` 就应当怀疑这个结论。**

## 四、响度与动态

| 指标 | 算法 | 怎么读 |
|---|---|---|
| `rms_dbfs` | `20·log10(RMS)` | 整体响度的绝对值 |
| `peak_dbfs` | `20·log10(max\|x\|)` | 峰值 |
| **`crest_db`** | `20·log10(peak / rms)` | **波峰因数**，越小压得越狠 |
| `dyn_range_db` | 分段 RMS 的 `P95 − P10` | 段间动态 |

**波峰因数是判断"响度战争"最直接的指标。** 参考区间：

- `> 16 dB` —— 动态保留良好，常见于古典、爵士、老录音
- `12–16 dB` —— 正常流行乐
- `8–12 dB` —— 明显压缩，现代商业制作主流
- `< 8 dB` —— 极度压缩，常见于硬核电子、响度战争产物

## 五、频谱特征（`features`）

对每帧做 `rfft`，取幅度谱：

| 指标 | 定义 |
|---|---|
| `centroid_hz` | 幅度加权平均频率 —— **亮度** |
| `rolloff85_hz` | 累积能量达 85% 处的频率 |
| `bass_ratio` | 20–250 Hz 能量占比 |
| `mid_ratio` | 250–2000 Hz |
| `high_ratio` | 2000–11025 Hz |
| `flatness` | 几何均值 / 算术均值 —— **噪声性 vs 音调性** |

`flatness` 接近 1 说明频谱平坦（白噪、镲片、失真）；接近 0 说明能量集中在少数谐波（纯音、清音吉他）。

## 六、节奏密度（`onset_rate`）

**起音密度 = 每秒检测到的起音次数**，反映编曲的密集程度。

```
谱通量 flux[t] = mean( max(0, spec[t] − spec[t−1]) )      # 只取能量上升
  ↓ 归一化
  ↓ 自适应阈值 thr = mean(flux) + 0.5·std(flux)
  ↓ 峰选取：越过阈值后爬到局部极大，记一次起音
  ↓ 100 ms 不应期（避免同一次击打被重复计数）
```

> 不应期是必要的：不加的话，一次钢琴击弦的衰减尾会被切成十几个"起音"。

## 七、BPM（`tempo_est`）—— 为什么不当结论用

```python
自相关(flux) × 对数正态先验(中心 125 BPM, σ=0.9 倍频程)
```

**它算出来了，但项目不把它当结论。** 原因是**八度歧义**：

- 175 BPM 的曲子，自相关在 87.5 BPM 处同样有峰
- 密集电子乐里，四四拍的每一下都可能被当成一拍
- 强先验会把结果往 125 附近拽

**报告里的 BPM 来自模型判断，不是这个函数。** 本地估计只作为交叉参考。

这是本项目一个刻意的取舍：**宁可在文档里承认不可靠，也不给出一个看起来很精确的错数字。**

## 八、模型侧（`describe`）

### 音频怎么送进去

```
ffmpeg -vn -i <src> -ac 1 -ar <rate> -b:a 128k  →  mp3
  ↓ base64
  ↓ 内嵌进 messages 的 input_audio 块
  ↓ payload 写入 work/payload.json
  ↓ curl -N --data-binary @payload.json
```

**两个必须记住的坑：**

1. **`-vn` 不能省**。不少 FLAC 的内嵌封面实际是 WebP 却标成 PNG，ffmpeg 遇到会直接报错退出。跳过视频流就没事。

2. **大 body 必须走文件**。`curl -d '<4MB base64>'` 会撞上内核的 `ARG_MAX`：

   ```
   OSError: [Errno 7] Argument list too long
   ```

   4 MB 左右就能触发。`--data-binary @file` 完全不经过 argv。

### 关闭思考链

```python
payload["enable_thinking"] = False          # 阿里云百炼认这个
payload["thinking"] = {"type": "disabled"}  # 部分厂商认这个
```

**两个字段同时下发**，因为不同厂商的约定不一样。DeepSeek 官方只认后者，百炼认前者。同时给，两边都不报错。

实测省约 **35%** 输出 token。

### 提示词要求模型输出什么

固定九个板块，便于聚合：风格/流派、乐器与音色、结构（带时间轴）、速度与节奏感、人声、情绪、和声、制作、整体印象。

**要求给时间轴**，是因为这样模型的"结构"描述才可核对 —— 它说 00:52 进副歌，你可以自己跳过去听。

## 九、聚合（`aggregate`）

读全部 `<曲名>.json`，做九类分布统计，输出 `REPORT.md`：

曲风构成 · 编制偏好 · 情绪图谱 · 语言分布 · 大小调 · 调性分布 · 速度分布 · 结构偏好（首次副歌时间） · 声学特征中位值

**声学部分用中位数而非均值** —— 音乐特征分布常带长尾（一两首极端实验曲就能把均值拉走）。

**语言分布读 `.lrc` 歌词文件判定**，不从音频猜。没有歌词文件的标为未知：**宁可缺失，不要瞎猜。**

## 十、已知边界

| 项 | 状态 |
|---|---|
| 调性 | 依赖 KK 轮廓，对无调性/强转调不可靠 |
| BPM | 本地算法有八度歧义，改用模型判断 |
| 首次副歌时间 | 模型输出，非节拍跟踪，存在误差 |
| 语言 | 依赖 `.lrc`，纯音乐无此项 |
| 结构分段 | 模型描述，不建议当精确时间码使用 |
| 情绪标签 | 模型主观判断，仅作分布参考 |

**这个工具描述的是"你的库里有什么"，不是"你应该听什么"。** 它不做推荐。
